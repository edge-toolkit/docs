# Code of Conduct

This policy records the adoption of a code of conduct for every repository and community space of the edge-toolkit
organisation.

## Purpose

The edge-toolkit organisation is a university team that accepts contributions from students, researchers and external
collaborators. Without a published code of conduct there is no shared definition of acceptable behaviour, no documented
channel for reporting problems, and no agreed consequences when behaviour falls short. GitHub also flags repositories
without one in their community profile, which discourages outside contributors.

## Policy

The organisation adopts the [Contributor Covenant, version 2.1][covenant], adapted only by filling in the reporting
contacts in its Enforcement section. It is a well-established code of conduct that is widely used by open-source and
university-affiliated projects, and GitHub recognises it automatically.

[covenant]: https://www.contributor-covenant.org/version/2/1/code_of_conduct.html

The canonical copy lives at `CODE_OF_CONDUCT.md` in the organisation's
[community health repository](https://github.com/edge-toolkit/.github), the location GitHub reads default community
health files from, so GitHub applies it to every repository in the organisation that lacks its own copy.

Reports of unacceptable behaviour go to the policy owner at <john.vandenberg@curtin.edu.au>, as named in the
Enforcement section of the document itself. A report that concerns the policy owner goes instead to Curtin
University's Integrity and Standards Unit at <ISU-CaseManagement@curtin.edu.au>, which handles complaints under the
[Curtin University Code of Conduct](https://www.curtin.edu.au/integrityandstandards/code-of-conduct/); staff of the
university are bound by that code in addition to this one. Whoever a report concerns is recused from the
investigation and any decision.

## Scope

This policy applies to every member of, and contributor to, the edge-toolkit organisation, in all community spaces:
repositories, issue trackers, pull requests, discussions and chat, as well as any online or offline event where someone
officially represents the organisation.

## Compliance

GitHub shows the code of conduct in each repository's community profile. For repositories without their own copy it
comes from the organisation's community health repository.

## Roles

Community leaders, in the Covenant's terms, are the maintainers of the repositories of the organisation. The policy
owner receives reports, coordinates investigations and decides on consequences.

## Enforcement

Violations are handled using the Covenant's four Community Impact Guidelines, in escalating order: Correction, Warning,
Temporary Ban and Permanent Ban. The full definitions are in
[the code of conduct file](https://github.com/edge-toolkit/.github/blob/main/CODE_OF_CONDUCT.md).
